# AI and automation rules | AI 与自动化修改规则

## 中文

任何 AI 助手、脚本或自动化工具修改本项目时：

- 先阅读 README、相关模块和当前 Git 状态；尊重现有未提交修改。
- 只处理明确提出的范围。未经作者明确指示，不替换、下载、生成或删除媒体，不扩大功能范围。
- 新增或替换第三方素材前，先记录来源 URL、作者、许可证、下载日期、再分发/修改权限依据、处理步骤和 SHA-256；许可不清楚时标记为待核实，不宣称已获授权。
- 不把第三方代码、素材、图标或文字描述为项目作者原创。
- 签名密钥、密码、令牌、账号信息和私人配置不得进入 Git、日志、PR、APK 以外的公开附件或聊天输出。
- 不运行会删除历史、重写共享分支或清理用户文件的操作，除非作者明确授权。
- 不推送、不更改仓库公开性、不创建或发布 Release、不发送对外消息；必须先取得作者针对该动作的明确授权。
- 只报告实际运行过的检查和测试；区分本机检查、浏览器预览与 Android 真机验证。

## English

When an AI assistant, script, or automation modifies this project:

- Read the README, relevant modules, and current Git state first; preserve uncommitted work.
- Stay within the explicitly requested scope. Do not replace, download, generate, or delete media, or expand functionality, without the author's direction.
- Before adding or replacing third-party media, record its source URL, creator, license, download date, redistribution/modification evidence, processing steps, and SHA-256. Mark unclear rights as pending; do not claim permission has been obtained.
- Do not describe third-party code, media, icons, or text as original work by the project author.
- Never place signing keys, passwords, tokens, account data, or private configuration in Git, logs, PRs, public attachments, or chat output.
- Do not delete history, rewrite shared branches, or clean user files without explicit authorization.
- Do not push, change repository visibility, create or publish a Release, or send external messages without explicit authorization for that action.
- Report only checks and tests actually run. Distinguish local checks, browser preview, and Android device testing.
